# 砚火（InkForge Local）

一个面向中文长篇小说创作的本地优先写作工作台。它通过 llama.cpp 的 OpenAI 兼容接口调用本地 GGUF 模型，支持续写、按要求创作、重写、扩写、文风分析、人物卡、章节管理、关键词世界书、分层长期记忆、章节规划与连续性审计。

## 设计思路

- 像 SillyTavern 世界信息一样，世界书条目可由关键词或正则触发，也可设为常驻；支持主词任一/全部、二级 AND/NOT 筛选、递归关联、人物与章节作用域、互斥组、权威等级、三种注入位置和独立 token 预算。
- 提示词不是一整块字符串，而是由核心指令、总纲、人物、相关世界书、文风卡、章节摘要、当前正文、作者注和本次任务分层编排。
- 文风“学习”采用本地模型提取风格卡 + 原文节选示例的方式，不会训练或修改模型权重。它适合快速迁移叙事视角、句法节奏、用词和意象习惯。
- 文风样例会按当前场景的对话比例、句长、节奏和内容相关性动态选择，不再固定使用样文开头。
- 续写时会单独锚定原文最后一句和最后两段，禁止复述、重开场景或伪造旧信件与回忆中的事实。
- 支持短篇/中短篇与长篇/连载两种节奏控制，并可让 AI 提供三个主题和核心冲突方案供作者选择。
- AI 分层导演先分两次生成“详细全书故事圣经”和“分卷蓝图”，再按卷以 3 章小批次拆出逐章因果路线，最后才细化当前章；可逐层审核、编辑和单卷重跑。
- 每个拆章批次都有“起势/升级/收束”职责；非最终批次不得提前兑现卷末结果，后批次会读取本卷全部已用章名和章末变化，避免跨批重复。质量门会同时检查章名、目标、冲突、转折与章末变化，并拦截非收束批次提前兑现卷末状态；若仍未通过，系统会把具体错误反馈给模型再做一次全批重写，最终仍不合格才保留旧路线。
- 完整的分卷路线可以一键批量建立章节；同步时不会覆盖已有正文或作者自定义章名。
- 所有结构化 AI 步骤都采用流式 JSON 闭合早停和任务总时限；本地模型超时、断连或返回残缺 JSON 时会给出可编辑降级结果，不再中断创作链。
- v0.9 起，详细全书总纲会随计划章数增长；全书圣经与分卷蓝图分开生成，避免 96 章长篇被压缩成几句口号。系统会检查总纲长度、分卷数量与章数总和、分卷/章节目标相似度、缺字段和非法数组；不合格结果不会覆盖旧规划。
- 写作提示词会为生成正文预留真实上下文空间，并使用更保守的中文 token 估算；大规模人物表优先保留主角群和当前场景相关人物，旧的无关开放线索不会挤掉近期章节与关键事实。
- 记忆提取中的“需要作者确认”会保存到故事记忆，可标记已处理，并在后续规划、写作和审计中持续提醒；项目体检同时统计未回收线索与待确认备注。
- AI 审计与本地检查采用更严格的一票否决：长度、重复、元话语等本地中高风险问题不会被 AI 的“通过”覆盖；审计建议仍可逐条勾选后生成最小修订。
- 长规划显示持续计时并可主动停止；关闭存在未保存改动的页面时会先提醒，减少误关造成的数据丢失。
- 长时间运行的规划、灵感、文风分析、模型检测和草稿都绑定发起时的作品/章节，切换作品后旧结果不会串写。
- 顶栏“项目体检”会检查完全重复正文、正文缺摘要、未细化章节和大量重复章名；重复正文只能经用户勾选、二次确认后清理，并保留版本历史。
- 作品支持创建时命名、重命名和永久删除；章节支持新增、改名和删除，并阻止删除最后一个章节。
- 生成内容先进入草稿区，经确认后插入正文，避免覆盖手稿。
- 草稿、单章细化、审计和记忆提取都绑定发起时的章节；处理中切换章节不会再把摘要、计划或正文写到另一章。
- 审计问题可逐条勾选后交给 AI 做最小修订；修订只作用于候选草稿，支持撤销和重新审计，不直接覆盖正文。
- v0.10 起，审计会标明具体审计的是当前右侧哪一版草稿；AI 修订后旧审计卡立即失效，重新审计若同类问题仍出现会明确提示“上次修订未充分解决”，避免把旧结果误认为新结果。
- 作者注改为逐章保存，只约束当前章，不会无意间污染后续章节。
- “灵感孵化”可把一句想法扩展成两套完整开书方案，包含定位、贯穿冲突、故事发动机、详细大纲、人物、世界设定和硬规则；选定后可创建新作品并紧接着生成全书规划。
- 空白章节可使用“AI 自动规划并写本章”：缺少执行计划时先自动细化，再按计划生成候选草稿；作者仍保留审阅、审计、插入正文和更新记忆的确认权。
- v0.11 新增“一键创作全文”：只输入灵感与禁区，系统会新建作品并自动完成推荐方向、故事圣经、详细全书规划、分卷拆章、逐章细化、正文、审计、最多两轮修订和记忆回灌。任务状态持久化到 SQLite，可暂停、恢复；应用意外退出后会停在最后检查点。
- 全文自动导演默认采用单模型串行生产，适配 8GB 显存；某章连续修订仍不达标时，可选择记录“质量债务”继续，或严格暂停等待人工接管。运行期间作品会锁定手动保存，防止旧页面覆盖后台新正文。
- v0.12 增加专业数据恢复层：SQLite 使用 WAL 与写入等待保护；每章在手动保存、接纳草稿和导演写入前独立保留 20 个快照；完整项目 JSON 可以重新导入为独立副本；自动导演启动和删除作品前都会建立数据库备份。
- v0.13 增加长期角色与世界一致性层：人物卡拆分永久人格核心、动态状态、关系网、人物弧、硬边界和对白示例；世界书支持确定性递归与条件过滤；接纳章节后建立“显著描写账本”，后续提示词和审计会避免机械复用人物入场、外貌、动作、环境和比喻。
- v0.15.0 新增全稿级质量系统：跨章原句/段落复用检测、全书疲劳词、历史题材现代术语密度、章节相似度和分卷阶段雷同体检；分卷契约新增主要场域、时间跨度、不可逆变化、人物选择与新故事问题；自动导演遇到结构性重复会废弃候选重新起稿，连续系统性失败才触发质量熔断，防止带着同一种质量债生成整本书。
- v0.16.0 新增可追溯叙事状态：事实带来源、证据、有效期与替代关系；人物拆分稳定外貌、当前可变外观和有来源知情账本；关系变化独立保存；伏笔具备类型、推进阶段、回收条件、目标窗口、相关人物、知情者和静默债务。接纳章节会保存章节结算单，单章规划增加章节功能、视角、时间地点、开篇第一拍、场景因果拍、情绪转向、线索动作、章末状态和结尾类型；项目体检会报告线索债务与记忆来源问题。
- v0.14.0 完成自动导演可靠性重构：结构/连接故障与软质量问题分流；单章路线最多进行四轮定向改写并保留最佳完整候选；恢复前重新审查旧检查点，发现坏路线只回退到首个问题点；规划、单章细化和记忆降级统一记录为可展开的“规划质量债务”，不再因可修复的相邻章相似而整书停机。
- v0.13.8 增加章节岗位一致性质量门：不仅比较字面重复，还会拦截“目标写风险或反常证据，转折却再次证明旧方案正确、迫使他人认可”的伪变化；12 类岗位各自带有明确禁令。
- v0.13.7 为逐章路线增加 12 类不可互换剧情岗位和状态维度轮换：危机授权、首次试验、反常证据、政治阻击、修正代价、对手反制、联盟裂缝、外部后果、合法性损失、终局两难、不可逆准备、卷末兑现。模型不能连续把“同一方案再次验证”换词当作新章节目标。
- v0.13.6 为自动导演增加逐章路线事务：分卷拆章不再在内存中一次处理整卷，而是每次只生成一章路线并立即保存。第 N 章失败时从第 N 章继续，界面显示当前卷路线 X/Y，且保留跨章去重和禁止提前兑现卷末状态的质量门。
- v0.13.5 将每卷详细蓝图继续拆成“剧情梗概核心 → 转折与人物弧执行清单”，两个子步骤分别保存。终卷契约和终局内容较长时，不再要求本地模型一次输出全部字段；失败可从当前卷的执行清单继续。
- v0.13.4 将分卷因果契约也改为逐卷生成和逐卷保存，避免 8–12 卷契约数组在本地 9B 模型上截断或丢失根字段。全书层现在可从任意一卷契约或任意一卷详细蓝图恢复。
- v0.13.3 将自动导演的全书规划拆成“故事圣经 → 固定分卷因果契约 → 逐卷详细蓝图”。96 章长篇不再要求本地模型一次输出数千字大纲；每卷蓝图立即保存，最终由全部卷目标、冲突、梗概、转折和卷末状态合成详细全书大纲。
- v0.13.2 将自动导演开书进一步拆成“故事骨架 → 精简人物名单 → 逐张人物卡 → 世界书”四段事务。每张人物卡生成后立即保存；本地模型超时或 JSON 截断时，只从未完成人物继续，不再重做已经完成的骨架和人物卡。
- v0.13.1 将自动导演的“灵感开书”拆成可恢复的两个小检查点：先生成唯一故事骨架，再单独生成人物卡与世界书；不再调用面向人工选择的“两套完整方案”，避免本地 8–12B 模型因重复生成两份大纲而反复过短或超时。恢复时只重跑未完成的小步。
- 自动导演会把每章采用的模型、审计分数、修订次数、问题和状态回写警告保存在章节运行记录中；质量债务可以展开查看并直接跳回对应章节，项目体检也会统一统计。
- 长期记忆检索新增类型配额与相似内容抑制，避免大量近似粮册、人物状态或旧线索挤占上下文；状态回写会拒绝未知人物、无效线索状态和越界重要度，并留下人工确认警告。
- 本地审计新增模型输出截断、未闭合标点、Markdown/说明文字、超长段落与重复句式起笔检查；流式连接在 llama.cpp 无响应 10 分钟后会安全释放，不再无限挂起。
- 项目数据只存储在本机 `data/inkforge.db`，自动备份位于 `data/backups/`，默认轮换保留 12 份。

架构思路参考了 [AI-Novel-Writing-Assistant](https://github.com/ExplosiveCoderflome/AI-Novel-Writing-Assistant) 的导演式整本生产流程、[InkOS](https://github.com/Narcooo/inkos) 的规划—编排—写作—审计—状态更新链路、[Long-Novel-GPT](https://github.com/MaoXiaoYuZ/Long-Novel-GPT) 的分级扩写与相关片段检索，以及 [SillyTavern](https://docs.sillytavern.app/usage/core-concepts/worldinfo/) 的关键词世界信息机制。本项目是面向单个本地 llama.cpp 模型重新实现的轻量方案，没有复制这些项目的源代码。

## 长篇防跑偏机制

砚火不会把整本小说粗暴塞进上下文，而采用十六层控制（完整设计见 [叙事记忆与小说质量架构](NARRATIVE_MEMORY_ARCHITECTURE.md)）：

1. **长期作者意图**：记录全书最终方向，不被单章灵感随意覆盖。
2. **全书总导演板**：固定主题命题、读者承诺、故事驱动器、贯穿冲突与终局代价。
3. **分卷战略**：每卷只负责一个阶段变化，明确卷目标、人物弧、关键转折和卷末状态。
4. **逐章路线**：按卷生成连续的“结果→问题→选择→代价”因果链，可批量建章。
5. **本章执行计划**：写作前结合实际进展细化目标、冲突、开篇第一拍、场景因果拍、必须保留/避免、转折、章末状态和结尾类型。
6. **永久人物核心**：稳定人格、价值观、恐惧、矛盾、语言指纹和硬边界只随明确人物弧事件改变。
7. **场景人物状态**：目标、位置、伤势、物品、情绪、可变外观和知识边界按接纳正文回写；稳定外貌不会被临时衣着覆盖。
8. **条件世界书**：只激活当前人物、章节和场景真正相关的权威设定，并沿条目内容做有限递归关联。
9. **可追溯事实记忆**：原子事实带来源章节、正文证据、有效区间、置信状态和替代关系。
10. **人物知情与关系账本**：分别维护“谁知道什么、如何知道、是否只是推测”和动态关系/信任/信息差。
11. **伏笔生命周期**：记录埋设、推进、延后、可回收、已回收，以及预期兑现、必要条件、时机和静默债务。
12. **事件时间线**：事件带参与者、地点、直接前因和已发生后果，形成轻量因果图。
13. **全书滚动摘要与章节结算单**：滚动摘要压缩主因果链，每章结算单保留具体增量及其来源。
14. **相关性检索与上下文预算**：按当前场景提取相关记忆，同时强制纳入过期线索债务，不全量注入历史正文。
15. **续写、文风与去重锚定**：最后一句、场景边界契约、局部文风指纹、人物对白示例及近期显著描写账本靠近任务注入。
16. **写后审计**：检查人物人格/声音、知识来源、关系、伏笔回收条件、因果拍、道具、伤势、位置、时间、世界规则和显著描写复用。

提示词预览会显示每个上下文区块的优先级、估算 token、检索命中的记忆以及预算裁剪轨迹。全项目历史最多保留 40 个；当前章节另有最多 20 个可单独恢复的快照。生成结束后还会立即检查长度、元话语、重复原文、重复段落、循环措辞、常见 AI 套话、统计文风偏移、疑似截断，以及原文未提供却被候选稿突然坐实的明确往事。

## 慢速本地模型的安全降级

正文创作仍然采用流式输出，不限制模型逐步写作。需要一次返回 JSON 的规划、分析和审计步骤则采用“AI 优先、本地可继续”：

- 全书规划失败：从已有总纲识别分卷标题、范围和阶段内容，并明确标记为备用结构，等待重新生成 AI 详细规划。
- 分卷拆解失败或未通过重复度/完整性检查：保留该卷原有路线，不用模板路线覆盖。
- 单章细化失败：把章节路线和权威故事事实转换为执行计划。
- 记忆提取失败：正文照常保存，只生成保守基础摘要，不擅自推断人物状态和事实。
- 连续性审计失败：明确标为“仅完成本地检查”，返回长度、重复、元话语、疑似新增往事和文风偏移检查，不会用本地分数冒充完整 AI 审计通过。
- 文风分析失败：根据句长、段长、对话占比和节奏生成本地统计文风卡。
- 灵感推荐失败：围绕已有核心冲突提供代价、关系和信念三种结构化方向。

黄色提示表示当前结果是降级结果，作者可以直接审核、修改并继续下一步；它不会冒充完整 AI 分析。

## 1. 启动 llama.cpp

先准备好 `llama-server.exe` 和一个适合中文创作的指令模型 GGUF，然后在 PowerShell 中运行：

```powershell
llama-server.exe -m D:\Models\your-model.gguf --host 127.0.0.1 --port 8080 -c 32768 -ngl 99
```

显存不足时降低 `-ngl`；内存或上下文不足时降低 `-c`。默认接口是 `http://127.0.0.1:8080/v1`。

## 2. 启动砚火

在项目目录右键打开 PowerShell：

```powershell
.\run.ps1
```

需要 Python 3.10 或更高版本。第一次启动会建立独立 Python 环境并安装依赖。浏览器访问：

<http://127.0.0.1:7860>

## 3. 推荐工作流

1. 想完全自动完成时，在“故事圣经”点击“一键创作全文”，输入灵感、偏好、章节数和每章字数；AI 会创建一个新作品并自动运行全链路。想逐层审核时，继续使用下面的专业流程。
2. 只有零散想法但想自己选择方向时，点击“灵感孵化”，输入人物、冲突、片段或一句话脑洞；从 AI 给出的两套完整方案中选择一套。
3. 选择“创建并自动生成全书规划”，审核主题、贯穿冲突、故事发动机、详细全书大纲、终局代价和分卷蓝图；作者只需修改不满意的部分。
4. 每次选择一卷点击“AI 拆解本卷”，审核逐章因果路线后点“批量建立/同步章节”。本地 9B/12B 模型分批生成，减少长 JSON 截断和章节重复。
5. 打开要写的章节。想完全交给 AI 时点“AI 自动规划并写本章”；想先审核小规划时先点“AI 细化本章”，修改后再点“开始创作”。
6. “本章作者注”只填写这一章的临时例外，例如“本章不揭示凶手”；不是必填，也不应重复长期规则。长期约束写入“本书硬规则”。
7. 正文为空的新章通常使用“按要求写”；同一场景已有正文、需要从末句接下去时使用“续写”；“重写/扩写选中”只对编辑器里选中的文字生效。
8. “卡住时：推荐下一步主题与冲突”不是每章必做。仅在现有路线不满意、剧情卡住或想比较替代走向时使用；“用于本次写作”只填入本次指令，“设为作品方向”会改变长期方向。
9. 把你有权使用的文章贴入“文风”，点击“分析并学习文风”。草稿先做“连续性审计”，修订后重新审计，确认后选择“插入并更新记忆”。
10. 用“提示词预览”检查分层规划、当前章作者注、命中的记忆与预算裁剪。发生误改时在“历史版本”恢复。

### 全文自动导演的停止与继续规则

- llama.cpp 持续断开、连续超时，或四轮均没有得到字段完整且闭合的 JSON：作为硬故障安全暂停，保留已经完成的阶段。
- 分卷拆章出现目标近似、岗位偏离或时代语言问题：自动改变状态维度和事件策略重试；仍未完全通过时选择差异度最高的完整候选，记录规划质量债务并继续，不丢失此前路线。
- 每次从检查点恢复都会重新复核已存路线；首个问题点之后的路线自动撤回并重建，已通过的前缀保持不变。
- 单章细化或记忆提取失败：分别使用上层章节路线或本地保守记忆继续，并记录规划/记忆债务。
- 严格模式下某章经过设定次数修订仍低于阈值：停在该章等待人工处理。
- 无人值守模式下同样情况会保存当前最佳稿、记录质量债务并继续；完稿后应重点复审这些章节。
- 浏览器可以关闭；砚火或 llama.cpp 关闭会中断当前调用，重启后点击“从检查点继续”。

完整的故障分类、检查点和恢复策略见 [自动导演可靠性架构](RESILIENCE_ARCHITECTURE.md)。

跨章重复、分卷阶段推进、疲劳词与连续质量债的设计见 [全稿质量架构](MANUSCRIPT_QUALITY_ARCHITECTURE.md)；《算尽苍生：秦策》的实际诊断和 84 章重构方案见 [秦策全稿重构执行稿](QINCE_MANUSCRIPT_REBUILD.md)。

## 模型建议

优先选择上下文较长、中文能力好、指令遵循稳定的 Instruct GGUF。7B/8B 可用于轻量续写，14B/32B 通常在人物一致性、长场景和文风控制上更好。应用不绑定具体模型。

## 当前边界

- 文风学习是 RAG/提示词层的“软学习”，不是 LoRA 微调。
- token 数为本地估算，用于预算提示；不同模型分词器会略有差异。
- 只有点击“插入并更新记忆”时才会让模型提取长期状态；提取结果仍可由作者修改。
- 连续性审计是第二次本地模型调用，能降低但不能完全消除事实错误，关键设定仍应由作者确认。
- 本地质量检测只负责可确定的机械问题；主题深度、人物复杂度和文学价值仍需作者判断。
- 请只使用你有权处理的样文；风格卡被设计为抽取一般写作特征，避免复制原句和专有设定。
